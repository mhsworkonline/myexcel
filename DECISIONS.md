# Design decisions

Decisions made autonomously while building MyExcel. Newest at the bottom.

1. **TypeScript 5.9 pinned** instead of TypeScript 7 (native port) because Next 15's build-time type checker targets the TS 5 API.
2. **HyperFormula license key `gpl-v3`.** HyperFormula is dual-licensed; using it under GPLv3 means MyExcel as distributed is GPLv3-compatible. A commercial HF license would be needed for closed-source distribution.
3. **Model is the source of truth for cell contents**; the engine mirrors it. Constant cells are read straight from the model, and only formula cells ask the engine. This keeps the UI fast and lets the engine be optional.
4. **Lazy engine attach.** Benchmarks show HyperFormula takes ~1.8 s and ~300 MB to load 1M cells. The engine is built only once the workbook contains a formula or a defined name, so large pure-data files (200k rows) open instantly.
5. **Structural edits (insert/delete rows/cols)**: the model shifts its sparse maps and HyperFormula adjusts formulas, then formula text is synced back from the engine. Undo of a delete = inverse insert + restore removed cells + restore every formula whose text changed.
6. **Styles** are flat objects deduplicated in a workbook-wide style table (`StyleTable`, id 0 = default). Whole-row/whole-column formatting is stored as row/column default styles, so formatting column A never materialises 1M cells.
7. **Default font** is Calibri 11 (with Carlito/Segoe UI fallbacks). No Microsoft fonts are bundled; Calibri is used only if installed on the system.
8. **Scroll extent** grows like Excel: used range plus a buffer, extended as the user scrolls, so the native scrollbar stays usable within browser element-size limits.
9. **INR / lakh-crore grouping** is triggered by the locale tag `[$₹-4009]` (en-IN) in a number format, matching how Excel stores Indian currency formats in .xlsx.
10. **Circular references** display 0 (as Excel does) and the status bar shows "Circular References: <cell>".
11. **Formula reference shifting** (copy/paste, fill, sort) is done by our own tokenizer in `model/formula.ts` rather than HyperFormula's clipboard, so the model stays the source of truth.
12. **`src/state/` application layer** sits between `model/` and `ui/`: the Zustand store plus all user actions. Actions build a `Tx` (transaction) which applies changes immediately and records inverse data, then commit one undoable entry. The UI calls actions and reads values through `state/values.ts`; only `engine/` imports HyperFormula.
13. Layout caches (column/row offsets) key on the identity of the size maps. Size maps are never mutated in place; every change replaces the map through the command layer.
14. **Extra dependencies for Phase 3**: SheetJS CE 0.20.3 (from cdn.sheetjs.com, the maintained build — the npm `xlsx@0.18.5` has known vulnerabilities) used *only* to read legacy `.xls`; JSZip for `.ods` read/write and post-processing ExcelJS output (charts, constant names, MyExcel metadata); jsPDF for PDF export.
15. **Pivot tables are computed snapshots** written into cells (like Excel's pivot cache): they update on Refresh or when their field layout changes, not on every source edit.
16. **Charts render as SVG overlays** positioned in sheet coordinates (px at 100% zoom). In `.xlsx` they are written as native DrawingML charts (column/bar/line/pie/doughnut/area/scatter/combo) so Excel opens them; MyExcel-only settings (style, colors) also go into a custom XML part for lossless round-trip.
17. **MyExcel metadata** that has no ExcelJS support (pivot definitions, sparklines, scenarios, full chart specs) is stored in `customXml/myexcelN.xml`, a standard custom XML part Excel preserves and ignores.
18. **Printing / PDF** reuses the canvas grid renderer: each page is rendered with a print viewport (print titles act like frozen panes), headers/footers are drawn in the margins, and jsPDF embeds the page images. Text in the PDF is therefore raster (not selectable).
19. **What-if Data Tables** are written as static values (recomputed when the dialog is re-run) rather than a live `{=TABLE()}` array.
20. **Tauri v2** desktop shell: the web build is exported statically (`TAURI_BUILD=1 next build` → `out/`) and loaded by Tauri. `TauriFileAdapter` uses the dialog and fs plugins, so Save writes back to the original path. Native menu commands are emitted to the web UI as `menu` events; a file passed on the command line (file association / "Open with") is picked up through the `startup_file` command. The regular web build is unchanged.
21. The 200k-row scroll check lives in `scripts/scroll-check.mjs` as a one-off tool, not part of the test suite. Measured: steady ~16.7 ms frames while wheel-scrolling; opening the file takes ~12 s (ExcelJS parse).

## Desktop (Tauri v2, Windows) — second pass

22. **Environment verified before starting:** Rust 1.96.1 stable `x86_64-pc-windows-msvc`, Visual Studio 2022 Build Tools (C++ toolset), WebView2 runtime 154, Node 22.16. Nothing was missing.
23. **Audited the earlier Tauri scaffold and finished it** rather than redoing it: kept the crate layout, startup-file command and file associations; replaced the broad `fs:scope **` capability, added CSP, window sizing, settings/recovery storage, close prompt, clipboard and WebView2 shortcut handling.
24. **Static export for every build.** `next.config.mjs` always uses `output: 'export'` (the app already had no API routes, SSR data, server actions or `next/image`). `npm start` now serves `out/` with a 30-line local static server (`scripts/serve-static.mjs`, bound to 127.0.0.1) instead of `next start`, which doesn't support exports. Next telemetry is disabled in all scripts.
25. **Settings, recent files and recovery live behind `FileAdapter`.** Desktop: `settings.json` (theme, default zoom, default font, recent files) in the app config dir, recovery snapshot at `recovery/snapshot.json` in the app data dir, both written atomically (temp file + rename). Web: localStorage for settings, IndexedDB for recovery. On Windows Tauri's `$APPCONFIG` and `$APPDATA` both resolve to `%APPDATA%\app.myexcel.desktop`, so "recent files in app data" and "recent files in settings.json" are the same file.
26. **Recovery** snapshots every 30 s while there are unsaved changes (both builds). Saving or choosing "Don't Save" on close deletes the snapshot; a crash leaves it, and the next launch offers Recover/Discard. A recovered workbook keeps its original path, so Ctrl+S writes back to it.
27. **Save in place:** Ctrl+S writes to the opened path for `.xlsx/.xlsm`, `.csv`, `.tsv/.txt` and `.ods`, choosing the writer from the file's extension. `.xls` is read-only (no writer), so Save on an `.xls` goes to Save As `.xlsx`, like Excel's compatibility flow.
28. **Least-privilege capabilities.** Only the commands used (read/write/exists/mkdir/remove/rename, open/save/message dialogs, set-title/close/destroy, event listen, path). fs scope is limited to `$APPDATA`/`$APPCONFIG`; user files become reachable only when the user picks them in a native dialog (the dialog plugin grants that exact path) and `tauri-plugin-persisted-scope` remembers those grants so Recent files still open after a restart. A file passed at launch is granted individually in Rust (`allow_file`). No HTTP/shell/updater plugins.
29. **CSP** `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src ipc: http://ipc.localhost; object-src/frame-src/worker-src 'none'`. Tauri adds hashes for the static export's inline bootstrap scripts at build time. `'unsafe-inline'` styles are required by React inline style attributes. `devCsp` is off because the Next dev server needs eval for HMR.
30. **Fonts bundled locally:** Carlito (SIL OFL, metric-compatible with Calibri) via `@fontsource/carlito`, so cell text looks the same on machines without Calibri and nothing is fetched remotely.
31. **Native menu shortcuts are display-only** (`"Save\tCtrl+S"` labels, no native accelerators). The web UI already implements every shortcut; native accelerators would either fire commands twice or swallow keys from text fields. Menu clicks emit a `menu` event routed to the same functions as the ribbon (`src/ui/desktop.ts`).
32. **WebView2 browser shortcuts disabled** (`AreBrowserAcceleratorKeysEnabled = false`, plus default context menu and status bar) via `with_webview`, because Tauri doesn't expose it. This stops Ctrl+F/Ctrl+P/F5/Ctrl+R/Ctrl+Shift+I from triggering browser features, while copy/paste/undo in text fields still work. Uses `webview2-com 0.39`/`windows 0.62`, matching Tauri's own versions.
33. **Title bar:** native window frame and controls are kept; the in-app title row shows file name and save status, and the native window title mirrors it (`Budget • Not saved – MyExcel`).
34. **Native clipboard:** Ctrl+C/X/V use the webview's copy/paste events (WebView2 converts `text/html` to CF_HTML), and the ribbon/menu Copy/Paste use two Rust commands (`clipboard_read`/`clipboard_write`, `clipboard-win`) that read and write "HTML Format" + Unicode text together, so they work without browser permission prompts and Excel pastes formatting.
35. **Close prompt** uses `onCloseRequested` + the dialog plugin's Save / Don't Save / Cancel message box; the web build keeps `beforeunload`.
36. **Default font** is per workbook (`props.defaultFont`, from settings when a workbook is created): cells without an explicit font render in it and are written with it to `.xlsx`, so files keep their look in Excel. Opening an existing file uses the file's own (Calibri) default.
37. Installers: NSIS and MSI. `webviewInstallMode` is `downloadBootstrapper` (Windows 10/11 already ship WebView2; the bootstrapper only runs on machines without it). The app itself makes no network requests.
